# Единый сайт и Telegram-бот Выхино

Документ описывает рабочую схему версии 3.0: Django + PostgreSQL — центр магазина, Telegram-бот — отдельный интерфейс без самостоятельной базы заказов.

## 1. Единые данные

| Область | Где хранится и кто изменяет |
|---|---|
| Товары, варианты, фото, наличие | Django-панель, PostgreSQL |
| Цены, дополнения, промокоды, самовывоз, доставка | Серверный расчёт Django |
| Заказы с сайта и из Telegram | Одна таблица `Order`, источник отмечен отдельно |
| Платежи и чеки | Только сайт и выбранный банк |
| Согласия | Общий `LegalAcceptance`, канал Telegram указан в User-Agent |
| Сертификаты и баланс | `GiftCertificate` + неизменяемый журнал операций |
| Корзина Telegram | Техническая SQLite бота, не источник цен |
| Фото перед выдачей | Заказ в Django, показ на сайте и в боте |

## 2. Настройка секретов

Сгенерируйте секрет минимум из 32 случайных символов, лучше 48–64:

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

Сайт `.env.production`:

```dotenv
BOT_API_SECRET=уникальный-секрет
BOT_ADMIN_IDS=123456789,987654321
```

Бот `.env`:

```dotenv
BOT_TOKEN=отдельный-токен-Telegram
ADMIN_IDS=123456789,987654321
SHOP_API_URL=https://домен/api/bot/v1
SHOP_API_SECRET=тот-же-секрет
YOOKASSA_SHOP_ID=
YOOKASSA_SECRET_KEY=
```

Не используйте для API Telegram-токен, пароль PostgreSQL или банковский ключ. Секреты не попадают в Git, журналы, сообщения Telegram или браузер.

## 3. Защита API

Каждый запрос содержит:

- HMAC-SHA256 от времени, пути и тела;
- временную метку с допустимым отклонением до 5 минут;
- одноразовый nonce, сохраняемый в Redis;
- ограничение тела 64 КиБ;
- ограничение частоты запросов;
- идемпотентный ключ для операций записи.

Сервер проверяет Telegram ID владельца заказа. Для сотрудников ID должен быть в `BOT_ADMIN_IDS`.

Идемпотентность предотвращает дубли заказа, отмены, оплаты сертификата и действий сотрудников при повторной отправке. Повторный запрос возвращает сохранённый ответ.

CSRF для служебного API заменён проверкой HMAC: сессии браузера и cookies здесь не используются. На боевом домене обязателен HTTPS.

## 4. API-операции

Все адреса начинаются с `/api/bot/v1/` и принимают только POST:

| Операция | Адрес |
|---|---|
| Магазин, товары, дополнения, контакты | `bootstrap/` |
| Расчёт корзины | `quote/` |
| Доступные дата и время | `availability/` |
| Создание заказа | `orders/` |
| История и детали | `orders/list/`, `orders/detail/` |
| Отмена нового неоплаченного заказа | `orders/cancel/` |
| Платёж и обновление статуса | `orders/payment/` |
| Покупка, проверка и список сертификатов | `certificates/purchase/`, `check/`, `list/` |
| Обращение менеджеру | `leads/` |
| Отзывы | `reviews/`, `reviews/list/` |
| Панель сотрудников | `staff/orders/`, `staff/status/`, `staff/paid/`, `staff/stock/` |

Для чтения каталога аутентификация тоже обязательна: служебная схема едина и не создаёт дополнительный публичный API.

## 5. Заказ из Telegram

1. Бот получает каталог с сайта.
2. Корзина хранит только ID товара, варианта, дополнения и количество.
3. Перед показом суммы бот запрашивает расчёт у сайта.
4. Дата и время запрашиваются у `availability/`.
5. Клиент открывает документы и нажимает явное подтверждение.
6. Сайт повторно проверяет форму, наличие, цены, слоты, согласия и итог.
7. `create_order` создаёт заказ с `source='telegram'` и Telegram ID.
8. Сохраняются согласия на оферту и ПДн; IP Telegram не выдумывается.
9. Повторное нажатие использует тот же ключ идемпотентности.
10. Платёж создаёт сайт; бот показывает ссылку и статус.

Клиент видит только свои заказы. Другой Telegram ID получает 404. Сотрудники работают через отдельные защищённые операции.

## 6. Сертификаты

### Покупка

Сертификат можно купить на странице `/certificates/` или в боте. Заказ имеет тип `certificate`. После подтверждения оплаты банком сайт выпускает код автоматически и один раз.

### Оплата заказа

- Код нормализуется к виду `ABCD-EFGH-JKLM`.
- Можно оплатить весь заказ или его часть.
- Баланс блокируется транзакцией и уменьшается вместе с созданием заказа.
- Каждая операция записывается в `GiftCertificateLedger`.
- При полном покрытии способ оплаты становится `certificate`, заказ считается оплаченным без банковского платежа.
- При отмене потраченная сумма возвращается один раз.

Срок действия — 365 дней. Правила чеков, аванса и возвратов до запуска проверяются с бухгалтером и банком.

### Проверка кода

Пять неверных попыток одного Telegram ID за 30 минут приводят к временной блокировке. Не передавайте код в общих чатах: владелец кода может использовать его как платёжное средство.

## 7. Работа владельца

1. Меняйте товары, цены, наличие и правила в Django-панели.
2. Не редактируйте каталог отдельно в боте.
3. Новые заказы сайта и Telegram появляются в общей очереди.
4. Подтверждайте, собирайте и загружайте фото в заказ.
5. Статусы из Telegram-панели меняют тот же заказ.
6. Отзывы из Telegram не публикуются автоматически — включайте после проверки.
7. Смотрите сертификаты и их журнал, а не только текущий баланс.
8. Операции бота доступны в «Операции бота» для разбора повторов и ошибок.

## 8. Запуск PostgreSQL

Для публичного сервера используется PostgreSQL 17 из `compose.yaml`, Redis и постоянные тома. SQLite разрешён только для локальной разработки сайта и технических данных бота.

Перед первым запуском:

1. Заполните `.env.production`.
2. Задайте уникальный `DJANGO_SECRET_KEY`, `POSTGRES_PASSWORD`, `BOT_API_SECRET`.
3. Настройте домены, `SITE_URL` и HTTPS.
4. Запустите миграции и контейнеры.
5. Создайте владельца.
6. Заполните магазин Выхино, не Курскую.
7. Проверьте реальные фото и медиа.
8. Настройте ежедневные копии и восстановление.

## 9. Регулярная очистка и резервные копии

Ответы служебного API хранятся до 90 дней. Настройте ежедневный запуск:

```bash
python manage.py cleanup_bot_operations
```

В Docker Compose выполняйте команду внутри контейнера `web`. Перед обновлением и ежедневно делайте копии PostgreSQL и media. Восстановление проверяйте на отдельной тестовой базе, а не на рабочих заказах.

## 10. Приёмка

Обязательные сценарии:

- одинаковые цена и наличие на сайте и в боте;
- вариант и музыкальная открытка;
- самовывоз и доставка;
- сертификат полностью и частично;
- отмена с одним возвратом баланса;
- повторное нажатие оформления без дубля;
- чужой заказ недоступен;
- сотрудник без прав не меняет данные;
- реальный платёж, чек и возврат;
- фото заказа видно в обоих интерфейсах;
- восстановление PostgreSQL на тестовой базе.

Запуск нельзя считать завершённым, пока эти проверки не выполнены на боевой конфигурации.
