# MuzFlowers Выхино — Telegram-бот единого магазина

Версия 3.0. Бот работает только с магазином **Выхино** и не создаёт независимый магазин со своими ценами и заказами.

Репозиторий: [github.com/Kirill010/muzflowers](https://github.com/Kirill010/muzflowers). Бот находится в папке `bot/` рядом с Django-сайтом.

## Архитектура

```text
Покупатель на сайте ───────────────┐
                                  │
Покупатель в Telegram ── aiogram ─┴── подписанное API ── Django ── PostgreSQL
                                                           ├── каталог и наличие
                                                           ├── цены и промокоды
                                                           ├── заказы и оплата
                                                           ├── согласия
                                                           ├── сертификаты
                                                           └── фото перед выдачей
```

- **Django и PostgreSQL — единственный источник истины.**
- SQLite бота хранит только корзину, контакты, черновики и служебные ключи повторных операций.
- Рабочий бот без `SHOP_API_URL` и `SHOP_API_SECRET` не запускается.
- Банковские ключи боту не нужны. Платёж создаёт и проверяет сайт.
- Прямого доступа бота к PostgreSQL нет.

## Что умеет покупатель

- Открыть каталог с актуальными ценами сайта.
- Выбрать букет и размер.
- Добавить музыкальную открытку или другое дополнение; обязательное примечание запрашивается отдельно.
- Изменить количество и очистить корзину.
- Ввести промокод или сертификат.
- Оформить доставку или самовывоз.
- Выбрать дату и доступное время.
- Указать другого получателя.
- Открыть и принять документы перед заказом.
- Оплатить онлайн, при получении, переводом или сертификатом.
- Увидеть заказы, статусы и фото собранного букета.
- Повторить или отменить новый неоплаченный заказ.
- Купить электронный сертификат и проверить его баланс.
- Написать менеджеру и отправить фото желаемого букета.
- Оставить отзыв после выполненного заказа; публикация проходит проверку.

## Что умеет сотрудник

Раздел «👑 Панель» доступен только Telegram ID из `ADMIN_IDS`, которые также внесены в `BOT_ADMIN_IDS` на сайте:

- видеть активные заказы;
- менять статусы по общему процессу;
- отмечать оплату;
- менять наличие;
- получать напоминания о неподтверждённых заказах;
- получать обращения и фотографии клиентов.

Фото собранного букета сотрудник загружает в Django-панели в карточке заказа. Клиент видит его и в боте, и на секретной странице заказа.

## Подготовка

### 1. Старые секреты

Если старые ключи когда-либо были публичны, их нужно **отозвать**, а не просто удалить из Git:

- Telegram: @BotFather → `/mybots` → бот → **API Token → Revoke current token**.
- ЮKassa: выпустить новый секретный ключ и проверить операции в кабинете.

Старые репозитории с секретами в истории лучше сделать приватными. Токен из этого README никуда не вставлять.

### 2. Сайт с PostgreSQL

Следуйте `README.md` и `docs/vykhino-bot.md` сайта. Для рабочего магазина обязательны:

- домен и HTTPS;
- PostgreSQL 17;
- Redis;
- постоянные тома базы и media;
- резервные копии с проверенным восстановлением.

### 3. Общий API-секрет

Сгенерируйте новый независимый секрет:

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

На сайте в `.env.production`:

```dotenv
BOT_API_SECRET=сгенерированный-длинный-секрет
BOT_ADMIN_IDS=123456789,987654321
```

В боте в `.env`:

```dotenv
BOT_TOKEN=новый-токен-от-BotFather
ADMIN_IDS=123456789,987654321
ORDERS_CHAT_ID=-1001234567890
SHOP_API_URL=https://ваш-домен/api/bot/v1
SHOP_API_SECRET=тот-же-длинный-секрет
YOOKASSA_SHOP_ID=
YOOKASSA_SECRET_KEY=
```

`ADMIN_IDS` и `BOT_ADMIN_IDS` должны совпадать по смыслу: это сотрудники, которым разрешены действия через API. Telegram ID виден после команды `/myid`.

Для локального просмотра `SHOP_API_URL` и `SHOP_API_SECRET` можно оставить пустыми: бот попробует `127.0.0.1:8000` и `127.0.0.1:8001`. Для публичного сервера оба значения обязательны.

### 4. Запуск

1. Установите Python 3.11 или новее.
2. Запустите `start.bat` на Windows или на сервере:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m flowerbot
```

3. Напишите боту `/start`.
4. Напишите `/myid` и сверьте ID с настройками.

На одном компьютере запускайте только один экземпляр бота. При повторном запуске он остановится с сообщением «Бот уже запущен» — это защита от конфликта Telegram `getUpdates`.
5. Проверьте каталог: цены должны совпадать с сайтом.

## Проверка перед реальными клиентами

1. Выберите букет и размер.
2. Добавьте музыкальную открытку и песню.
3. Проверьте доставку и самовывоз.
4. Проверьте промокод и сертификат.
5. Прочитайте и примите документы.
6. Проведите заказ и нажмите оплату второй раз — дубля быть не должно.
7. Убедитесь, что заказ появился в Django-панели.
8. Подтвердите заказ и загрузите фото.
9. Проверьте статус и фото в боте.
10. Проведите настоящий тестовый платёж и возврат через банк.
11. Проверьте, что другой Telegram ID не видит заказ и не открывает панель сотрудника.
12. Восстановите резервную копию PostgreSQL на тестовой базе.

## Как обновлять

1. Сделайте резервную копию PostgreSQL и media.
2. Обновите сайт и бота отдельно.
3. Примените миграции сайта.
4. Запустите тесты обоих проектов.
5. Проверьте API и один полный заказ.
6. Только затем переводите реальных клиентов на новую версию.

Не меняйте API-секрет одновременно с массовым оформлением заказов: остановите бота, смените секрет на сайте и в боте, затем запустите снова.

## Тесты

Из корня репозитория на Windows:

```bash
bot\.venv\Scripts\python -m unittest discover -s bot/tests -t bot
```

На Linux:

```bash
bot/.venv/bin/python -m unittest discover -s bot/tests -t bot
```

Проверяются старые и новые сценарии, подпись API, идемпотентность, корзина, варианты, дополнения, оформление, сертификаты, менеджер и права сотрудников. Реальные Telegram и банк тестами не имитируются — для них нужна отдельная приёмка.

## Основные файлы

- `flowerbot/integrated_app.py` — запуск Выхино.
- `flowerbot/integrated_handlers.py` — сценарии покупателя и сотрудника.
- `flowerbot/shop_api.py` — подписанный HTTP-клиент.
- `flowerbot/integrated_store.py` — корзина, контакты и идемпотентные ключи в SQLite.
- `tests/test_integrated.py` — полные пользовательские сценарии через имитацию Telegram.
- `tests/test_shop_api.py` — подпись и ошибки API.

`shop.toml` и `catalog.toml` относятся к прежней автономной версии и тестам совместимости. **В рабочем режиме Выхино цены и наличие берутся только с сайта.**
