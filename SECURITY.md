# Muzflowers — безопасность

## Что уже сделано в коде
- Цены, скидка и доставка считаются на сервере по данным БД. Цены из браузера игнорируются.
- CSRF-защита Django: токен берётся из cookie и уходит в заголовке `X-CSRFToken`.
- Проверка входных данных: длины полей, телефон (≥10 цифр), дата (от сегодня до +90 дней), количество (1–50), не более 30 позиций, время доставки только из белого списка.
- Лимиты по IP: заказы — 10 в час, проверка промокода — 15 за 10 минут (защита от спама и подбора кодов).
- Защита от XSS: данные из БД передаются через `json_script` и экранируются перед вставкой в разметку; цвета в админке принимают только `#RRGGBB`.
- Запросы идут через ORM (нет SQL-инъекций), заказ создаётся в транзакции, у позиции хранится цена на момент заказа.
- Согласие на обработку персональных данных обязательно и проверяется на сервере.
- Эндпоинта для просмотра заказов нет — номер заказа наружу ничего не открывает.

## Что нужно сделать вам перед запуском
1. **Прод-настройки** (отдельный `settings_prod.py` или переменные окружения):

       import os
       DEBUG = False
       SECRET_KEY = os.environ['DJANGO_SECRET_KEY']      # не хранить в git
       ALLOWED_HOSTS = ['ваш-домен', 'www.ваш-домен']
       CSRF_TRUSTED_ORIGINS = ['https://ваш-домен']
       SECURE_SSL_REDIRECT = True
       SESSION_COOKIE_SECURE = True
       CSRF_COOKIE_SECURE = True
       SESSION_COOKIE_HTTPONLY = True
       # CSRF_COOKIE_HTTPONLY не включать: JS читает токен из cookie
       SECURE_HSTS_SECONDS = 31536000                    # после проверки, что HTTPS работает везде
       SECURE_HSTS_INCLUDE_SUBDOMAINS = True
       SECURE_CONTENT_TYPE_NOSNIFF = True
       SECURE_REFERRER_POLICY = 'same-origin'
       X_FRAME_OPTIONS = 'DENY'
       DATA_UPLOAD_MAX_MEMORY_SIZE = 100_000
       CACHES = {'default': {'BACKEND': 'django.core.cache.backends.redis.RedisCache',
                             'LOCATION': 'redis://127.0.0.1:6379/1'}}
       SHOP_CLIENT_IP_HEADER = 'HTTP_X_REAL_IP'          # только если nginx сам выставляет этот заголовок

   Лимиты работают корректно только с общим кэшем (Redis или Memcached): у `LocMemCache` счётчик свой в каждом процессе.
   Без `SHOP_CLIENT_IP_HEADER` за nginx все посетители выглядят как один IP, и лимит сработает на всех сразу.
2. Выполните `python manage.py check --deploy` и исправьте все предупреждения.
3. **Админка:** смените адрес `/admin/`, задайте длинные пароли, включите 2FA (например, `django-otp`), курьерам дайте отдельную группу с правом только просматривать заказы.
4. **HTTPS** обязателен. Медиафайлы отдавайте через nginx, а не через Django; в `static()` в `urls.py` режим только для разработки.
5. Закрепите версии в `requirements.txt` на поддерживаемом LTS Django и периодически запускайте `pip-audit`.
6. **Content-Security-Policy** (например, через `django-csp`): скрипты и стили свои, шрифты с `fonts.googleapis.com` и `fonts.gstatic.com`. В разметке остаются inline-атрибуты `style=`, поэтому для `style-src` понадобится `'unsafe-inline'`, либо их нужно вынести в классы.
7. **Персональные данные** (имя, телефон, адрес): добавьте страницу политики конфиденциальности и ссылку на неё у чекбокса, ограничьте доступ к базе и бэкапам, не пишите телефоны в логи. Требования зависят от страны (152-ФЗ, GDPR) — это стоит согласовать с юристом.
8. **Уведомления о заказах** (Telegram, email): имя, адрес и текст открытки — пользовательский ввод, экранируйте их под формат сообщения (HTML-режим Telegram, заголовки письма).
