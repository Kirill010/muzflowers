# MuzFlowers — сайт цветочного магазина

Интернет-магазин: каталог букетов, корзина, заказ с самовывозом или доставкой, **музыкальная открытка**, предоплата,
личный кабинет клиента и **панель владельца**, где всё меняется без программиста.

## Как запустить (3 шага)

1. Установите **Python 3.12 или новее** с [python.org](https://www.python.org/downloads/).
   На первом экране установщика поставьте галочку **Add Python to PATH**.
2. Дважды щёлкните по файлу **`start.bat`** (Mac и Linux: в терминале `./start.sh`).
   Первый раз подождите 2–3 минуты: подготовятся программы и база. Ничего не закрывайте.
3. Откроется сайт: **http://127.0.0.1:8000**. Панель владельца: **http://127.0.0.1:8000/admin/**.

При первом входе в панель сайт попросит **придумать логин и пароль** — запишите их.
Остановить сайт: закройте чёрное окно.

> Сайт на вашем компьютере видите только вы. Чтобы его увидели покупатели, его нужно выложить в интернет — см. ниже.

## Как пользоваться панелью владельца

Откройте `/admin/`. На первой странице — **«Что сегодня?»**: новые заказы, заказы на сегодня, завтра и ближайшие две недели,
цифры за неделю и месяц и список **«Что осталось заполнить»** (реквизиты, фото, оплата, уведомления).

| Что нужно | Что нажать |
|---|---|
| Принять заказ | На карточке заказа кнопки по порядку: **Подтвердить → Собран → Выдан** (для доставки: **Передан курьеру → Доставлен**). Пришла предоплата — кнопка **Оплачен** |
| Распечатать заказ | На карточке: **Бланк** (лист A5 в формате вашей тетради предзаказов) или **Список на завтра** |
| Распечатать музыкальную открытку | На карточке заказа: **Открытка** — с текстом клиента и QR-кодом песни |
| Скачать заказы в Excel | **Заказы** → отметьте галочками → внизу «Действие» → «Скачать таблицу (Excel)» |
| Поменять цену | **Букеты** → поправьте цену прямо в списке → «Сохранить» |
| Цветов сегодня нет | **Букеты** → снимите галочку «Есть сегодня» → «Сохранить» (букет виден, но заказать нельзя) |
| Добавить букет | **Букеты → Добавить**. Фото загружайте как есть — сайт сам повернёт и уменьшит. Нет фото — сайт нарисует букет сам |
| Сезонные цветы | В букете укажите «Сезон: с месяца / по месяц» — вне сезона заказать нельзя |
| Размеры букета с разной ценой | В букете блок «Размеры» |
| Телефон, часы работы, цена доставки, предоплата | **Настройки сайта** |
| Реквизиты ИП (обязательно по закону) | **Настройки сайта → Реквизиты продавца** |
| Праздник или выходной | **Особые дни** → дата → «Заказы не принимаем» или лимит заказов на день |
| Временно не принимать заказы | **Настройки сайта → Пауза** |
| Акция с промокодом | **Промокоды (акции)** — обязательно поставьте срок действия |
| Музыкальная открытка и другие добавки | **Дополнения к заказу** |
| Вопросы и ответы на сайте | **Вопросы и ответы** |
| Адрес Выхино | **Точки (магазины)** → Выхино → впишите адрес → включите «Показывать» |
| Настоящие отзывы | **Отзывы** (только с разрешения клиента; выдуманных отзывов на сайте нет) |
| Заявки от офисов и на подписку | **Заявки** — менять статус «Новая → В работе → Закрыта» |

Правило магазина зашито в сайт: **заказ на другой день принимается только по предоплате**.
Включается и выключается в «Настройках сайта» (галочка «Заказ на другой день — только с предоплатой»).

## Что вписать перед запуском для покупателей

В панели на первой странице есть список **«Что осталось заполнить»**. Главное:

1. **Реквизиты продавца** (имя ИП и ИНН) — они показываются в оферте и внизу сайта.
2. **Адрес и часы работы** — проверьте, что всё верно. Телефон и часы взяты с вашей печатной продукции.
3. **Цены и доставка** — цены взяты из вашего списка из 11 букетов, доставка (300 ₽, бесплатно от 3 000 ₽) — **предположение**: поменяйте на настоящую.
4. **Фото букетов** — сделайте свои фото (не берите фото чужих магазинов).
5. **Как принимать предоплату** — впишите реквизиты для перевода в «Настройках» или подключите онлайн-оплату (ниже).
6. **Юрист**: попросите проверить «Публичную оферту» и «Политику конфиденциальности» (`templates/shop/offer.html`, `privacy.html`).
7. Сделайте **тестовый заказ** со своего телефона.

## Уведомления о заказах в Telegram

1. В Telegram найдите **@BotFather**, напишите `/newbot`, придумайте имя — получите ключ вида `123456:ABC...`.
2. Впишите его в файл `.env`: `TELEGRAM_BOT_TOKEN=ваш-ключ`.
3. Создайте группу для заказов, добавьте в неё бота и напишите в группе любое сообщение.
4. В папке сайта откройте командную строку и выполните `.venv\Scripts\python manage.py telegram_setup` — она покажет номер чата.
   Впишите его: `TELEGRAM_CHAT_ID=номер`. Перезапустите сайт.
5. Проверка: `.venv\Scripts\python manage.py telegram_setup --test` отправит пробное сообщение.

Письма клиентам и сотрудникам настраиваются в `.env` (блок «Почта», `ORDER_NOTIFY_EMAILS`). Без настройки письма печатаются в чёрном окне.

## Онлайн-оплата (необязательно)

Нужен договор интернет-эквайринга с Т-Банком (Т-Касса) или ЮKassa — его оформляете вы.

1. В `.env` впишите `PAYMENT_PROVIDER=tbank` (или `yookassa`) и ключи (подсказки — в `.env.example`).
2. В личном кабинете банка укажите адрес уведомлений: `https://ваш-сайт/payments/webhook/tbank/` (для ЮKassa — `/payments/webhook/yookassa/`).
3. Если банк подключил вам онлайн-кассу, оставьте `PAYMENT_RECEIPT=1` и проверьте систему налогообложения (`PAYMENT_TAXATION`).
4. **Обязательно сделайте тестовый платёж** из кабинета банка до запуска. Код оплаты написан по документации банков, но с вашими ключами его ещё никто не проверял.

## Как выложить сайт в интернет

Нужны: сервер с Docker (лучше в России — персональные данные россиян по закону хранят на территории РФ), домен, HTTPS и обратный прокси.

На своём компьютере остаётся SQLite, чтобы `start.bat` работал без сервера БД. Для нового боевого сайта рекомендуется `compose.yaml`: PostgreSQL для базы, Redis для общих лимитов между процессами, отдельный том для фотографий. Старый `docker run` без PostgreSQL по-прежнему подходит только для небольшого сайта с SQLite.

1. Создайте на сервере `.env.production` по образцу `.env.example`. Заполните `DJANGO_DEBUG=0`, `DJANGO_SECRET_KEY`, `DJANGO_ALLOWED_HOSTS`, `DJANGO_CSRF_ORIGINS`, `SITE_URL`, `DJANGO_BEHIND_PROXY=1`, `DJANGO_SETUP_TOKEN` и `POSTGRES_PASSWORD`. Пароль PostgreSQL для Compose должен состоять из букв, цифр, `-` и `_`: он подставляется в адрес подключения.
2. Запустите новый сайт и дождитесь здоровых контейнеров:

```
docker compose --env-file .env.production up -d --build
docker compose --env-file .env.production ps
```

3. HTTP-порт слушает только `127.0.0.1:8000`: настройте nginx или прокси хостинга для домена и HTTPS. Не открывайте PostgreSQL и Redis наружу.
4. Создайте первого владельца по адресу `https://ваш-сайт/accounts/setup/?token=ВАШ_КОД`, затем смените одноразовый код.
5. Проверьте заказ с телефона, Telegram-уведомление и тестовый платёж.

**Перенос существующего SQLite — отдельный шаг.** Сначала сделайте копию `db.sqlite3` и `media`, остановите запись заказов и только затем переносите данные в пустую PostgreSQL-схему через `dumpdata`/`loaddata` до запуска `seed_shop`. Простое указание нового `DJANGO_DB_URL` создаёт пустую базу и ничего не переносит. Файл выгрузки содержит персональные данные: храните его защищённо и удалите после проверки. Медиафайлы переносятся отдельно.

**Копии:** сохраняйте том `muz-data` с фотографиями и PostgreSQL-том `muz-postgres`. Для логической копии PostgreSQL:

```
docker compose --env-file .env.production exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc' > muzflowers-backup.dump
```

Делайте копию ежедневно и периодически проверяйте восстановление на отдельной тестовой базе. Восстановление поверх боевой базы выполняйте только после остановки записи и создания свежей копии.

## Если что-то не работает

- **start.bat пишет «не найден Python»** — установите Python с галочкой *Add Python to PATH*.
- **Ошибка при установке программ** — проверьте интернет и запустите `start.bat` ещё раз.
- **Забыли пароль** — на странице входа нажмите «Забыли пароль?» (нужна настроенная почта) или попросите разработчика выполнить `python manage.py changepassword ваша-почта`.
- **Хочу начать с чистой базой** — закройте сайт и удалите файл `db.sqlite3` (и папку `media`), запустите `start.bat`.

## Для разработчика

```
muzflowers/      настройки (settings.py читает .env), адреса
shop/            магазин: models, pricing (цены), cart (корзина в сессии), slots (даты и время), orders (создание заказа),
                 payments (Т-Касса, ЮKassa), notifications, art (рисованные букеты), admin_site (панель владельца)
accounts/        вход по почте или телефону, кабинет, первый запуск (/accounts/setup/)
templates/       страницы; static/shop/ — стили и скрипты без сборки
```

- Тесты: `python manage.py test` (215). Боевые настройки: `python manage.py check --deploy`.
- GitHub Actions прогоняет весь набор на SQLite (Python 3.12 и 3.13) и PostgreSQL 17, проверяет Redis, Compose и запуск собранного Docker-контейнера.
- Все цены и итоги считает только сервер (`shop/pricing.py`); браузеру ничего не доверяем.
- Защита: CSRF, лимиты на заказы/вход/промокоды, защитные заголовки и CSP (без встроенных скриптов и стилей), проверка данных на сервере.
- Фото уменьшаются при загрузке, копии для страниц делаются на лету (`shop/thumbs.py`).
- Данные в базе: `SiteSettings` (одна запись), `Shop`, `Category`, `Product` (+`Variant`, `ProductImage`), `Addon`, `PromoCode`, `SpecialDay`,
  `Order` (+`OrderItem`, `OrderAddon`), `Lead`, `Review`, `FAQ`, `Profile`.
